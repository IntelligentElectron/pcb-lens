# PCB Lens command line

`pcb-lens` answers the same queries as the pcb-lens MCP server, one shell command each. When that MCP server is connected, use its tools instead.

## Install

Check for it with `pcb-lens --version`. If it is missing, either install the standalone binary:

```bash
curl -fsSL https://raw.githubusercontent.com/IntelligentElectron/pcb-lens/main/install.sh | bash
```

or run it through npm without installing, writing `npx -y @intelligentelectron/pcb-lens` wherever this guide writes `pcb-lens`.

## Usage

```bash
pcb-lens <tool> [file] --flag value ...
pcb-lens <tool> --help     # the tool's description and every flag
pcb-lens --help            # every tool
```

- The tool is its name below, in snake_case. Flags are its arguments, spelled exactly.
- The file the tool reads may be the first argument, or its flag (`--file`, or `--board` on the export tools).
- A flag takes the next word, or `--flag=value`. A value that starts with a dash needs `=`: `--pattern=-12V`.
- Quote regex patterns for the shell: `--pattern '^VCC'`.

## Output and exit codes

The result is the tool's JSON on stdout: indented in a terminal, one compact line otherwise, so pipe it to `jq` when it is long.

| Exit | Meaning |
|------|---------|
| 0 | The result answers the query |
| 1 | The result has an `error` field: a missing file, no match, an invalid pattern |
| 2 | Usage error: an unknown or missing flag, or a value of the wrong kind. The message and a usage line are on stderr |

## Workflow

1. `get_pcb_metadata` on an IPC-2581 file gives the layer stackup, units and size of the design.
2. `get_pcb_component` looks up one component by exact refdes; `get_pcb_net` traces nets by regex.
3. `get_constraints` on a .brd, .dcf or .tcfx file gives the design rules: without `--section` an overview of the sections, with it the objects of one section.
4. On Windows with Cadence installed, `export_cadence_ipc2581` turns a .brd into the IPC-2581 file the first two steps read.

```bash
pcb-lens get_pcb_metadata board.xml
pcb-lens get_pcb_net board.xml --pattern '^DDR_D[0-7]$'
pcb-lens get_constraints board.brd --section BrdPhysicalCSet
```

## Conventions

- Lengths, coordinates and trace widths from the IPC-2581 tools are in microns, whatever the file's own unit; rotation is in degrees counterclockwise
- A constraint section's `units` field names the unit of its lengths
- Read layout files only through these commands, not by parsing them yourself, and never run `pcb-lens update` or `pcb-lens uninstall`: they replace or remove the binary

## Tools

Each description is the MCP tool's own.

### get_pcb_metadata

Get a high-level overview of a PCB design file: file metadata, the layer stackup, design units, and the total component and net counts. Use this first to understand a design's size and layers before querying specific components or nets. For an Allegro .brd the layers are the copper layers, top to bottom.

- `--file` (required; string; may be the first argument). Path to an IPC-2581 XML file or an Allegro 16.x or 17.x .brd file.

### get_pcb_component

Look up a single component by its exact reference designator (refdes). Returns its placement (position, rotation, layer), package and BOM details, the nets connected to each pin, and a summary of its pads (count and the distinct pad shapes). The refdes must match exactly; it is not a pattern. Set detail='full' to additionally get the exact coordinate of every pad (sampled for components with very many pads).

- `--file` (required; string; may be the first argument). Path to an IPC-2581 XML file or an Allegro 16.x or 17.x .brd file.
- `--refdes` (required; string). Exact component reference designator (e.g., 'U5', 'C10', 'R22').
- `--detail` (string; default "summary"). How much to return. 'summary' (default) gives the pad count and distinct pad shapes. 'full' additionally returns the exact coordinate of each pad; components with very many pads are sampled. Use 'full' only when you need exact pad positions, since responses are larger.

### get_pcb_net

Look up nets in a PCB layout by name and inspect their connectivity and routing. Provide a net-name pattern (a regular expression); for each matching net you get the connected component pins (grouped by component), the layers the net uses, a per-layer routing summary (trace widths, number of routed segments, and total routed length), and a via summary (count per drill size). All distances are in microns. Copper that is filled as a pour or plane instead of drawn as a trace is reported as routed on its layer but without a width or length, so a net can be fully routed yet show no trace width. A net that returns pins but no routing was most likely exported without its routed-copper data. Use a specific pattern: one that matches every net in the design is rejected. Set detail='full' to additionally return exact geometry — every via coordinate and the full point-by-point shape of each routed trace (including arcs for curved traces); for very large nets this geometry is sampled and the response is marked truncated.

- `--file` (required; string; may be the first argument). Path to an IPC-2581 XML file or an Allegro 16.x or 17.x .brd file.
- `--pattern` (required; string). Regex pattern for net name (e.g., '^DDR_D0$', 'CLK', '^VCC_3V3$').
- `--detail` (string; default "summary"). How much to return. 'summary' (default) gives the per-layer routing summary and via counts. 'full' additionally returns exact geometry: every via coordinate and the full shape of each routed trace (its vertices, width, and arc data for curved traces); large nets are sampled and the response is marked truncated. Use 'full' only when you need exact coordinates, since responses are larger.

### get_constraints

Query layout constraints from a Cadence .tcfx file, a Constraint Manager .dcf file, or an Allegro .brd board (read directly, no Cadence install needed). Without a section name, returns an overview of all sections and object counts. With a section name, returns all constraint objects with their attributes, references, members and children. Common sections: PhysicalCSet, SpacingCSet, ElectricalCSet, NetClass, MatchGroup, DiffPair, Design (stackup), Region. A .brd also has Brd* sections decoded from its binary database (BrdPhysicalCSet, BrdNetClass, BrdNet, BrdStackup, ...): these are the board's live rules, while the XML sections are embedded Constraint Manager snapshots whose 'source' says where they came from.

- `--file` (required; string; may be the first argument). Path to a .tcfx, .dcf or .brd file.
- `--section` (string). Section name to query (e.g., 'PhysicalCSet', 'SpacingCSet'). Omit for overview.

### export_cadence_ipc2581

Export a Cadence Allegro .brd file to an IPC-2581 XML file, the format the other PCB query tools (get_pcb_metadata, get_pcb_component, get_pcb_net) read. Windows only, and requires a Cadence SPB installation (detected automatically).

- `--board` (required; string; may be the first argument). Path to Cadence Allegro .brd file.
- `--output` (string). Output path (without .xml extension — Cadence appends it). Defaults to <boardname>_ipc2581.xml next to the .brd.
- `--revision` (string). IPC-2581 revision to write: "B" (1.03) or "C" (1.04, the default). Rev C carries the most layout detail; prefer it unless a downstream tool needs Rev B.

### export_cadence_constraints

Export the design rules and constraints from a Cadence Allegro .brd file to a .tcfx file, which you can then read with get_constraints. Windows only, and requires a Cadence SPB installation (detected automatically).

- `--board` (required; string; may be the first argument). Path to Cadence Allegro .brd file.
- `--output` (string). Output .tcfx path. Defaults to <boardname>_constraints.tcfx next to the .brd.
